## 2. 根因分析

### R1 (fq='pre') — 数据拉取返回空

R1 日志第一行揭示了根因：

```
history end_date=None, context.previous_date=2025-03-31
```

`get_price(etf, fq='pre', end_date=context.previous_date, ...)` 返回了空的 DataFrame。这意味着 `fetch_field` 在 `fq='pre'` 模式下未能获取到任何 close/high/low/amount 数据。

由于 `close_df` 为空，`compute_trend_gates` 中的 `close[etf].dropna()` 返回空 Series，所有循环都无法满足 `len(series) < ma_window` 检查，所有 gate 保持为 0。全年 52 次周调仓，全部因 gate=0 而空仓。

### R2 (fq=None) — 数据拉取正常

R2 日志第一行：

```
history end_date=2025-03-31 00:00:00, context.previous_date=2025-03-31
```

`get_price(etf, fq=None, ...)` 正常返回了数据，趋势门槛正确判断（159819.XSHE=1, 518880.XSHG=1），信号链全部正常执行。

### 为什么 R3 (fq='pre', 区间 2025-11~2026-04) 能正常拉数据？

R3 同样使用 `fq='pre'`，但数据拉取正常（`history end_date=2025-10-31`）。这意味着问题**不是全局的 `fq='pre'` 不可用**，而是条件性的：

- R3 从 2025-10-31 倒数 717 天 → 约 2022 年底，所有 ETF 均已上市
- R1 从 2025-03-31 倒数 717 天 → 约 2022 年初，人工智能ETF易方达(159819.XSHE) 可能数据不足

但 `fetch_field` 是逐 ETF 拉取的，单个 ETF 失败不应影响其他。更可能的原因是：**JoinQuant 在特定 `end_date` + `fq='pre'` + `count` 组合下存在返回异常**，表现为所有 ETF 同时空返回。

## 3. FQ 口径决策

### 结论：**使用 `fq=None`（不复权）**

**依据：**

1. **可靠性**：`fq='pre'` 在至少一个真实回测区间（2025-04-01 ~ 2026-04-30, count≈850）中导致全部数据拉取失败，策略完全无效
2. **策略注释已预判**：代码注释明确指出"JoinQuant 不建议给含场内基金的策略开启动态复权"
3. **场内基金特性**：ETF 的分拆/合并信息披露可能不完整，前复权调整可能失真
4. **R2 (fq=None) 表现**：年化收益 21.31%、夏普 1.609，在相近区间内显著跑赢现金，信号链路完整

### 建议配置

```python
g.use_real_price = False
g.fq_mode = None
```
