# 性能分析报告 -- R5 无 Profile 对比回测

## 1. 性能分析概览

- 策略名称：ETF 多因子轮动策略（线性乘数版）
- 是否启用 `enable_profile()`：**否**
- 数据来源：R5 自身无 profile 数据（仅 18 条空记录）；性能对比依赖 R4 的 profile 数据（3065 条）
- 回测链接：<https://www.joinquant.com/algorithm/backtest/detail?backtestId=c7488e9834cae42a85355fd34fa31cbf>
- 对等 R4 链接：<https://www.joinquant.com/algorithm/backtest/detail?backtestId=ac5a03b99d8722f55b0a05a57554abf0>

### R4 vs R5 计算耗时对比

| 运行 | enable_profile | 实际计算耗时 | Profile 记录数 | 相对 R5 增量 |
|------|:---:|--------:|------:|------:|
| R4 | 是 | 2.134 min | 3065 | +77.4% |
| R5 | 否 | **1.203 min** | 18 | 基准 |

- **Profile 开销：+0.931 min（+77.4%）**
- R5 节省了约 44% 的计算时间（相对于 R4 的总耗时）
- 8.3 年全区间仅需 1.2 分钟，远低于聚宽 35 分钟预算上限

## 2. Profile 开销量化分析

### 2.1 时间开销

| 维度 | R4 (有 profile) | R5 (无 profile) | 差异 |
|------|--------:|--------:|------:|
| 云端计算总耗时 | 128.0 s | 72.2 s | **+55.8 s** |
| 单次周检查平均 | ~0.32 s | ~0.18 s | +0.14 s |
| 总调用次数（估算） | ~400 次 | ~400 次 | 0 |
| Profile 数据产出 | 3065 条 | 18 条 | +3047 条 |

### 2.2 数据量开销

| 指标 | R4 | R5 | 差异 |
|------|------|------|------|
| all_data.json 中 profile record_count | 3065 | 18 | +3047 |
| profile.md 文件大小 | ~60 KB（含完整函数级耗时） | ~50 B（仅空头信息） | ~60 KB |
| 其他 tabs_raw 数据 | 完全一致 | 完全一致 | 0 |

### 2.3 开销成因

`enable_profile()` 在每个函数进入/退出时插入计时代码，开销来自：
- 时间戳获取（`time.time()` 或等效调用，每次函数调用 2 次）
- 调用栈维护与累计耗时更新
- 结果序列化输出（回测结束时写入 profile 报告）

R4 的函数总调用次数估算（基于 profile 记录数 3065 和每个函数被记录一次或多次）约为 3000+ 次函数级计时点。在 400 次周级调仓中，平均每次调仓触发约 7-8 个被 profile 跟踪的函数。

## 3. 主要性能瓶颈（来自 R4 profile 数据）

由于 R5 关闭了 profile，无法直接观测函数级耗时。以下瓶颈分析完全基于 R4 的 profile 数据：

| 函数名 | 总耗时 | 占计算比 | 主要瓶颈 |
|--------|--------|------|----------|
| `get_history_data` | 37.65s | ~54% | 聚宽 `get_price` 批量取数（日线 OHLC + amount） |
| `fetch_field` | 36.30s | ~52% | 被 `get_history_data` 调用，单字段批次取数 |
| `compute_rsrs_multipliers` | 12.25s | ~18% | 滚动回归计算（N x M 窗口），向量化但仍重 |
| `compute_crowd_penalties` | 11.46s | ~16% | 五指标多窗口分位数计算 |
| `percentile_rank` | 2.71s | ~4% | 滚动分位数（被拥挤度模块频繁调用） |
| `execute_rebalance` | 2.51s | ~4% | `order_target_value` 下单执行 |
| `compute_momentum_scores` | 2.42s | ~3% | 多周期排名计算 |
| `_log_step` | 0.96s | ~1% | 格式化日志输出 |
| `compute_trend_gates` | 0.93s | ~1% | MA120 均线比较 |
| `compute_rp_weights` | 0.51s | ~1% | 逆波动率权重 |
| `compute_portfolio_vol_scale` | 0.39s | ~1% | 组合波动率缩放 |

> 注：`fetch_field` 的耗时已包含在 `get_history_data` 内。占比是基于 `weekly_check` 的总耗时 69.62s 计算。

## 4. 热点路径解读

### 数据获取（占 ~54%）

数据获取是最大瓶颈。每次周级调仓约取 800-1000 根日线 K 线（OHLC + amount，4-5 个字段），3 个 ETF 标的约取 15 个字段序列。聚宽的 `get_price` 是内存/磁盘查询，8 年 x 52 周 x 3 标的的累计数据拉取量可观。在无 profile 的 R5 中，此部分预估耗时约 36-38s（与 R4 相当，因 profile 对数据 I/O 影响较小）。

### RSRS 计算（占 ~18%）

RSRS 对每个标的做 RSRS_N x RSRS_M 窗口（默认 N=18, M=600）的滚动 OLS 回归（High ~ Low），计算 Beta 和 R-squared。8 年约 2000+ 个交易日的滚动均值，纯向量化 numpy 运算虽快但窗口大、频次高。

### 拥挤度计算（占 ~16%）

五指标（短期收益、中期收益、成交额偏离、价格偏离、波动率拥挤）在 CrowdWindow=200 窗口内计算分位数，每个指标需要独立的 `percentile_rank` 调用。

### Profile 额外开销路径

在 R4 中，这 12 个被跟踪的函数共计产生约 3000+ 次计时事件。每次事件涉及：
1. 函数入口处获取时间戳
2. 函数出口处获取时间戳并更新累计耗时
3. 将耗时数据写入 profile 存储结构

这约 3000 次 profile 事件合计贡献了额外的 ~56s 开销（R4 128s - R5 72s），平均每次 profile 事件约 18-19ms。这个开销在云端 Python 环境中偏高，可能与 profile 实现中的锁竞争或序列化有关。

## 5. 优化建议

| 建议 | 预期收益 | 实施难度 | 备注 |
|------|----------|:--:|------|
| **关闭 `enable_profile()`（正式回测）** | 节省 ~44% 计算时间 | 低 | 已通过 R4/R5 对比验证，策略指标无影响 |
| 缓存 `get_price` 数据：跨周复用日线仓位 | 节省 30-40% 取数时间 | 中 | 同一标的重复拉取历史日线，可缓存 |
| 降低 RSRS_M 默认值（800 -> 400） | 节省 ~8% RSRS 计算时间 | 低 | 需回测验证信号差异 |
| 使用 `get_bars` 替代 `get_price` 的部分字段查询 | 节省 10-15% 取数时间 | 低 | `get_bars` 对 OHLC 字段更高效 |
| `percentile_rank` 预计算：同窗口数据跨标的复用 | 节省 20-30% 分位数计算 | 中 | 拥挤度五指标的窗口相同时可合并 |

## 6. 建议优先级

1. **正式回测关闭 `enable_profile()`** -- 零成本节省 44% 时间，已通过本次对比验证安全
2. **缓存 `get_price` 数据** -- 最大单一收益，周级调仓天然适合缓存历史日线
3. **`get_bars` 替代 `get_price`** -- 改动小，聚宽 `get_bars` 对日线 OHLC 直接返回
4. **`percentile_rank` 跨标的复用** -- 减少滚动分位数重复计算

## 7. 结论

- **Profile 开销确认**：`enable_profile()` 在 8.3 年长周期回测中增加 77% 的计算时间（+56s），但对策略收益/风险/交易指标零影响
- **R5 性能优秀**：无 profile 的 8 年全区间回测仅需 1.2 分钟云端 CPU 时间，远低于 35 分钟预算
- **当前最大性能问题**：数据获取（`get_price`）占计算时间的 54%，是唯一值得优化的实质性瓶颈
- **推荐实践**：正式回测和批量测试关闭 `enable_profile()`；仅在性能调优或函数级诊断时临时开启
- **Profile 数据价值**：R4 的 profile 数据（3065 条）为后续性能优化提供了完整的函数级热点图谱，单次开启即可复用分析结论
