# C3-PERF-004 日志量评估

> 评估来源：R2（1 年基线）和 R4（8 年长周期）的回测日志

## 日志量对比

| 指标 | R2（1 年） | R4（8.3 年） | 说明 |
|------|-----------|-------------|------|
| INFO | 855 | 858 | 几乎相同（API 上限 1000） |
| WARNING | 94 | 142 | R4 略高（更长周期积累） |
| ERROR | 0 | 0 | 无运行时错误 |
| **总条目** | **949** | **1000** | 均接近 API 上限 |
| WARNING 比例 | 9.9% | 14.2% | 在合理范围 |
| 估算每日日志 | ~3.8/天 | ~0.41/天 | R4 因上限限制被低估 |

## 日志结构分析

每次周级调仓约产生 12-18 条 INFO 日志：
1. `history end_date=` — 数据窗口截止日
2. `[趋势门槛] TrendGate:` — 3 个标的的趋势过滤结果
3. `[动量分数] MomentumScore:` — 3 个标的的排名得分
4. `[TopK入选] Selected:` — 选入标的
5. `[风险平价权重] RPWeight:` — 风险预算分配
6. `[RSRS修正乘数] RSRSMultiplier:` — 价格结构修正
7. `[拥挤度惩罚] CrowdPenalty:` — 拥挤打折
8. `[组合波动率缩放] PortfolioVolScale=` — 总仓位缩放
9. `[最终权重] FinalWeight:` — 最终目标权重
10. 建仓/调仓提示（首次）或 WARNING（positions 不存在）
11. 下单反馈（`OrderTargetValue` + 成交价）

## 评估结论

### 日志量判定：**正常，无异常退化**

- 单次调仓日志量约 12-18 条，结构稳定，无递增趋势
- WARNING 全部为首次调仓时的 "positions 中不存在" 提示，属于聚宽 API 的正常行为，非策略问题
- 无 ERROR 日志，无 dead loop 或其他运行时异常
- `_log_step` 总耗时 0.96s（8 年累计），单次日志写入约 2.2ms，性能影响可忽略

### 潜在改进

- 若需进一步减少日志量，可考虑采样写入（如每 N 周输出一次完整链路，其余跳只输出最终权重）
- 首次调仓的 WARNING 可通过预检查 `context.portfolio.positions` 避免
