# 本地研究平台重构

如你有更好的建议，可以提出讨论。

目标：
1、所有研究工具，脚本都统一架构。
   1.1 采用策略库，数据中心，流程编排层，研究工具库 ，文档报告库，5层结构。
2、项目级别的数据中心，中心化管理 **所有** 回测数据。
   2.1 数据储存方式便于AI使用优先。
   2.2 数据存储体积小，读取快，持久化。
   2.3 数据可以复用到其他研究中。
3、流程编排层，轻量化，可以结合SKILL。
   3.1 尽量轻量化，足够灵活。
   3.2 可以将重复性比较确定的流程，形成流程模板来重复使用。
4、研究工具库
   4.1 工具库中的工具可以原子化复用到各种流程中。
   4.2 工具库函数化，Python 库化。
   4.3 重构AB测试功能，不再依赖GIT分支，而是扩展策略库的变体管理能力来实现。
5、扩展DOCS为文档和报告库
   5.1 集合所有文档和报告，建立灵活快捷的文档和报告索引和查询机制。
6、策略库管理策略，相同策略的各种变体，策略的专题研究等。

设计约束：
1、重构范围是整个项目目前所使用的全部工具。
2、重构计划可以分步骤的独立执行，各个步骤间无强耦合。
3、对于数据中心，流程模板，工具库，要形成标准化的结构和文档。
4、如和目标不冲突的情况下，尽量复用现有仓库约定。
5、记得更新仓库的持久化约定对齐最新的工作流程、更新依赖项，尽量减少漂移。

参考：可以参考聚宽网站，开源社区上的一些现有设计思路。
