# 长期项目防止开发规则漂移方案

## Why
防止开发规则和约定漂移，不能主要依赖"提醒大家遵守文档"，而要把规则变成一套可执行、可审计、可演进的工程治理系统：规则文档化，规则代码化，规则自动检查，合并前强制门禁，例外受控，定期审计。

## What Changes
- 四道防线：本地开发防线、PR 防线、主干保护防线、周期审计防线
- 规则分级：MUST / SHOULD / MAY
- 例外治理：waiver + owner + expiry + migration plan
- 本仓库落地方案：规则来源清晰 + Git 分支隔离 + 主干门禁保护

## Impact
最终目标是让正确做法成为默认路径，让错误做法无法无声进入主干，让例外不会变成新常态。
