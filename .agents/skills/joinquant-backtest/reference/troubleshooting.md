# 失败处理与重试策略

## 总原则

- 先判断是页面问题、登录问题、策略问题，还是本地落盘问题。
- 每类问题优先重试一次；重试仍失败时，再把证据整理给用户。
- 失败时要保留上下文：当前 URL、页面关键文本、报错片段、已生成文件清单。

## 常见问题处理表

| 问题类型 | 典型症状 | 首选处理 |
| --- | --- | --- |
| 页面元素缺失 | 选择器查不到、按钮不存在 | 刷新页面并重试一次；仍失败则记录页面文本并停下 |
| 登录失效 | 跳回登录页或页面要求登录 | 提示用户手动登录，登录后从列表页继续 |
| 编译失败 | 页面出现 `ERROR` / `Traceback` | 打开错误日志，修复本地策略后从上传步骤重来 |
| 正式回测超时 | 长时间不出现“回测完成” | 记录 URL 与状态文本，让用户决定继续等待或终止 |
| 数据提取异常 | 某个标签为空或长度异常 | 重新点击对应标签并再次抽取，必要时只补抽单个标签 |
| 本地落盘失败 | 目录创建失败、文件写入失败 | 重试创建目录与写入一次，仍失败则报告缺失文件 |

## 编译失败时应保留的证据

- 当前编辑页 URL
- `#daily-errors-tab` 中的错误日志
- 本地上传版本路径
- 最近一次修改过的策略文件路径

## 回测超时时的处理顺序

1. 记录当前 URL
2. 读取状态区文本
3. 判断是否仍在详情页
4. 若页面仍有明显进度变化，可以建议继续等待
5. 若页面状态长期无变化，交给用户决定是否终止

## 数据提取异常的判断标准

可以将以下情况视为“异常”，需要补救：

- 指标标签文本长度远小于预期
- `window.__bt` 中缺少关键键名
- `summary_metrics.json` 为空对象
- 详情页明显已完成，但 `profile` 文本始终为空

## 何时必须停下来问用户

以下情况不要自作主张继续：

- `start_date > end_date`
- 本地策略需要较大改写才能通过编译
- 回测超时且继续等待成本明显升高
- 聚宽页面结构变化，核心选择器全部失效
- 产物目录已存在多份冲突结果，且覆盖策略不明确

## 建议返回给用户的信息

当技能无法继续时，至少返回：

- 失败步骤编号
- 当前页面 URL
- 关键报错或状态文本
- 已生成文件
- 下一步建议
