# 日常增量验证提速方案设计

## 摘要
在 `docs/design/2026-05-29-incremental-governance-validation.md` 保存方案设计。核心策略：日常迭代不再默认跑完整 pathref、governance、skill owner 全链路，而是新增 repo-native affected 验证层；本地 PR 提交走 `pr-submit`，最终完整验证证据来自 GitHub `Research Governance / verify-full`。

参考成熟做法：pre-commit 默认面向变更文件，`--all-files` 适合全量场景；Nx 用 Git diff + project graph 跑 affected tasks；Pants 用目标/依赖元数据做细粒度缓存；Bazel/GitHub Actions 用输入键命中缓存。来源：pre-commit、Nx、Pants、Bazel、GitHub Actions cache。 ([pantsbuild.org](https://www.pantsbuild.org/stable/docs/python/overview/third-party-dependencies))

## 关键设计
- 新增三层验证合同：
  - `verify-fast`：日常迭代默认入口，只表示“可继续开发”，不作为 PR 或合并证据。
  - `verify-full`：完整 pathref + governance gate + 必要全局检查，作为 pre-push/CI/final 兜底；PR 合并证据来自 GitHub required check `Research Governance / verify-full`。
  - `verify-explain`：输出本次改动命中的检查、跳过的全量门禁、缓存命中情况和下一步建议。
- 新增仓库内轻量 affected 引擎，不引入 Pants/Nx/Bazel：
  - 输入来自 staged/worktree diff、可选 `--base`、可选 `--files`、PR Flow fragments。
  - 根据路径映射选择 scoped checks，不自动升级 full gate。
  - 普通 Markdown 只跑 changed-file pathref 检查；Skill 目录变更才跑 `skill_ownership check`；治理代码变更才跑 governance 相关 ruff/mypy/bandit/pytest；策略变更只跑对应 py_compile 和策略测试。
- 新增本地缓存：
  - 缓存在 `.local/governance-cache/`。
  - 缓存键包含 check id、命令参数、输入文件内容哈希、相关配置哈希、Python 版本和工具版本。
  - 只缓存通过结果；失败结果不缓存，避免隐藏最新错误。
- 更新 AI 助手规则：
  - 日常小改完成前默认运行 `verify-fast`。
  - 本地 PR 提交和 pre-push 不把 `verify-full` 作为前置证据；CI 或最终合并证据使用 GitHub `Research Governance / verify-full`。
  - 输出必须说明 fast 覆盖范围和 full 未运行事实。

## 接口变化
- 新增 CLI：
  - `.\.venv\Scripts\python.exe -m scripts.research.governance.verify fast`
  - `.\.venv\Scripts\python.exe -m scripts.research.governance verify full`
  - `.\.venv\Scripts\python.exe -m scripts.research.governance.verify explain`
- 新增 Makefile 入口：
  - `make verify-fast`
  - `make verify-full`
  - 保留 `make pre-pr` 作为手工完整门禁入口；PR 提交默认走 `pr-submit`，不把本地 `verify-full` 作为前置证据。
- 调整 hooks：
  - `.githooks/pre-commit` 改为 `verify fast --staged`。
  - `.githooks/pre-push` 只做主干保护和 local review fragments freshness 提醒，不运行本地 `verify full`。
- 扩展 pathref：
  - `scripts.tools.path_tools.refactor check --files <paths...>` 只检查指定 Markdown 文件内的 pathref。
  - 无 `--files` 时保持现有全仓行为。
- 不改变 `scripts.research.governance gate` 的强门禁语义。

## 测试方案
- 单元测试 affected 选择矩阵：
  - 普通 docs 改动不触发 full gate。
  - `.codex/skills/**` / `.claude/skills/**` 触发 skill owner scoped check。
  - `scripts/research/governance/**` 触发 governance ruff/mypy/bandit/pytest scoped checks。
  - `requirements*.txt` 触发 pip-audit。
  - `strategies/<name>/**` 触发对应策略 py_compile 和 tests。
- 缓存测试：
  - 同一输入二次运行命中缓存。
  - 修改文件内容、配置或 Python 版本后缓存失效。
  - 失败结果不缓存。
- hook/governance 测试：
  - governance audit 要求 pre-commit 使用 `verify fast --staged`。
  - CI 仍要求 `verify full`；pre-push 不运行本地 full gate。
- 接受标准：
  - 日常文档小改不会运行 `scripts.research.governance gate` full。
  - `verify-fast` 输出明确列出 checked/skipped/cache-hit/full-not-run。
  - `verify-full` 与现有完整门禁覆盖等价。

## 假设
- 方案优先解决日常迭代耗时；CI 仍保留完整兜底，PR 合并依赖 GitHub required checks。
- 日常 fast 通过只代表“可继续”，不代表“可合并”。
- 不引入新构建系统，只在现有 Python CLI、Makefile、hooks、规则文档内落地。
- 缓存仅放 `.local/`，不进入 Git。
