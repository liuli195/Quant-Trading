# 旧研究项目迁移指南

旧项目可以继续保留原有 CLI 与目录；新平台优先服务后续新增研究。若需要迁移，建议按以下顺序推进：

1. 先补 `project.json`，让项目能被统一 CLI 识别。
2. 把高频重复计算沉到 feature cache。
3. 将“全量研究”和“shortlist 精筛”拆成 `fast/full` 两段。
4. 把本地可判定、可 replay、必须上云的边界写入插件能力声明。
5. 最后再整理文档与共享数据引用。

## 迁移判定

只有同时满足以下条件，才值得迁移旧项目：

- 研究主题仍会继续复用；
- 已经存在明显的本地重复计算；
- 未来还会继续产生候选扫描或局部参数跟进；
- 迁移后能减少真实上云次数，而不只是让目录更统一。

## 当前建议

- `window_heterogeneity`：适合优先迁移到 `factor_scan`，因为它已经证明缓存后可进入亚秒级扫描。
- `momentum_tilt`：适合逐步沉淀为 `parameter_followup` 的 replay 参考实现。
- 一次性、不会再复用的专题报告：不必为了“整齐”强行迁移。
